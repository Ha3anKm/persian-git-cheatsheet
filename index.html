مرجع جامع Git و GitHub در VS Code

آموزش گام‌به‌گام از تنظیمات اولیه و پوش کردن پروژه تا مدیریت لاگ‌ها و رفع تمام خطاهای رایج

۰. پیش‌نیازها ۱. پوش پروژه جدید ۲. آپدیت پروژه ۳. تغییر رپوزیتوری ۴. دستورات کاربردی ۵. فایل gitignore. ۶. رفع خطاهای رایج

فقط یک‌بار در سیستم ۰. پیش‌نیازها و معرفی هویت به گیت

بعد از نصب برنامه Git روی سیستم، قبل از اینکه بتوانید اولین کامیت خود را ثبت کنید، باید نام و ایمیل اکانت گیت‌هاب خود را به گیت معرفی کنید. ترمینال VS Code را با کلیدهای Ctrl + ` باز کنید و این دو دستور را بزنید:

۱. تنظیم نام کاربری (به جای Your Name نام خود را بنویسید): 
git config --global user.name "Your Name"
۲. تنظیم ایمیل (ایمیل اکانت گیت‌هاب خود را وارد کنید): 
git config --global user.email "your_email@example.com"
نکته: به دلیل وجود --global، این کار را فقط یک بار پس از نصب ویندوز/گیت انجام می‌دهید و برای تمام پروژه‌های بعدی ذخیره می‌ماند.

شروع پروژه ۱. پوش کردن یک پروژه جدید در گیت‌هاب (برای بار اول)

ابتدا وارد سایت گیت‌هاب شوید و یک رپوزیتوری جدید و کاملاً خالی (بدون تیک زدن Add a README) بسازید. سپس پوشه پروژه را در VS Code باز کرده و دستورات زیر را به ترتیب در ترمینال اجرا کنید:

۱. راه‌اندازی گیت در پوشه پروژه (ساخت پوشه مخفی .git): 
git init
۲. افزودن تمام فایل‌های پوشه به لیست انتظار (Staging): 
git add .
۳. ثبت اولین نسخه در حافظه گیت:
git commit -m "Initial commit"
۴. تغییر نام شاخه اصلی به main:
git branch -M main
۵. اتصال پوشه به آدرس رپوزیتوری گیت‌هاب:
git remote add origin https://github.com/USERNAME/REPOSITORY-NAME.git
۶. ارسال فایل‌ها به گیت‌هاب برای بار اول: 
git push -u origin main

استفاده روزانه ۲. آپدیت کردن پروژه‌ای که قبلاً پوش شده است

تنظیمات گیتِ هر پروژه داخل همان پوشه ذخیره شده است. بنابراین حتی اگر پوشه را ببندید، روی پروژه‌های دیگر کار کنید و دوباره به پوشه قبلی برگردید، گیت خودش آدرس رپوزیتوری آن را می‌شناسد. بعد از هر ویرایش، فقط این ۳ دستور را بزنید:

۱. انتخاب تمام فایل‌های تغییریافته:
git add .
۲. ثبت تغییرات به عنوان یک لاگ جدید در تاریخچه: 
git commit -m "توضیح کوتاه درباره تغییرات انجام شده"
۳. ارسال آپدیت به گیت‌هاب:
git push
نکته: فایل‌های قبل از تغییر هرگز از حافظه گیت‌هاب پاک نمی‌شوند؛ بلکه تمام نسخه‌های قبلی در بخش Commits گیت‌هاب به صورت تاریخچه (Log) باقی می‌مانند.

تغییر مقصد ۳. ارسال پروژه فعلی به یک رپوزیتوری جدید

اگر می‌خواهید پروژه‌ای را از رپوزیتوری قبلی جدا کنید و از این به بعد روی یک رپوزیتوری جدید پوش کنید (بدون تغییر نام پوشه و بدون پاک شدن رپوزیتوری قبلی):

۱. تغییر آدرس مقصد به رپوزیتوری جدید:
git remote set-url origin https://github.com/USERNAME/NEW-REPOSITORY-NAME.git
۲. ارسال کل پروژه به رپوزیتوری جدید:
git push -u origin main

کنترل و بازیابی ۴. دستورات کاربردی مدیریت پروژه

دستوراتی که برای دانلود پروژه، بررسی وضعیت، دیدن لاگ‌ها و برگشت به نسخه سالم قبلی استفاده می‌شوند:

دانلود (Clone) یک پروژه آماده از گیت‌هاب روی سیستم: 
git clone https://github.com/USERNAME/REPOSITORY-NAME.git
مشاهده آدرس رپوزیتوری گیت‌هابِ متصل به پوشه فعلی: 
git remote -v
مشاهده فایل‌هایی که تغییر کرده‌اند ولی هنوز کامیت نشده‌اند: 
git status
مشاهده تاریخچه تمام کامیت‌ها (لاگ‌ها):
git log --oneline
لغو تمام تغییرات اخیر (قبل از کامیت) و بازگشت به آخرین نسخه سالم: 
git restore .

مدیریت فایل‌ها ۵. جلوگیری از آپلود فایل‌های اضافی با .gitignore

برای اینکه پوشه‌های سنگین (مثل node_modules) یا فایل‌های امنیتی (مثل .env) وارد گیت‌هاب نشوند، یک فایل دقیقاً با نام .gitignore در پوشه اصلی پروژه بسازید و نام موارد دلخواه را داخل آن قرار دهید:

نمونه محتوای استاندارد برای فایل .gitignore: 
node_modules/
.env
dist/
build/
.DS_Store

عیب‌یابی ۶. خطاهای رایج هنگام کار با Git و روش حل آن‌ها

اگر هنگام اجرای دستورات بالا با هر یک از پیغام‌های زیر مواجه شدید، مطابق راه‌حل مربوط به آن عمل کنید:

1. error: remote origin already exists.
علت: زمانی رخ می‌دهد که دستور git remote add origin را در پوشه‌ای می‌زنید که قبلاً یک آدرس گیت‌هاب به آن داده شده است.
راه‌حل: به جای add از دستور set-url استفاده کنید تا آدرس جدید جایگزین قبلی شود: 
git remote set-url origin https://github.com/USERNAME/REPOSITORY-NAME.git
2. ! [rejected] main -> main (fetch first) / error: failed to push some refs
علت: داخل رپوزیتوری گیت‌هاب فایلی وجود دارد (مثلاً هنگام ساخت رپوزیتوری تیک README یا .gitignore را زده‌اید یا مستقیم در سایت فایلی را تغییر داده‌اید) که روی سیستم شما نیست.
راه‌حل اول (پیشنهادی - ادغام فایل‌ها): ابتدا فایل‌های گیت‌هاب را بگیرید و بعد پوش کنید: 
git pull origin main --allow-unrelated-histories
راه‌حل دوم (پاک کردن محتوای گیت‌هاب و جایگزینی اجباری با فایل‌های سیستم شما): 
git push -u origin main --force
3. Author identity unknown / *** Please tell me who you are.
علت: گیت را تازه نصب کرده‌اید و هنوز نام و ایمیل خود را تنظیم نکرده‌اید، بنابراین اجازه git commit نمی‌دهد.
راه‌حل: نام و ایمیل خود را وارد کنید و سپس دوباره دستور کامیت را بزنید: 
git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"
4. error: src refspec main does not match any
علت: قصد دارید دستور git push را بزنید، اما هنوز هیچ کامیتی ثبت نکرده‌اید (یا فراموش کرده‌اید git add . و git commit بزنید).
راه‌حل: ابتدا فایل‌ها را اضافه و کامیت کنید و سپس پوش کنید: 
git add .
git commit -m "Initial commit"
git branch -M main
git push -u origin main
5. fatal: not a git repository (or any of the parent directories): .git
علت: ترمینال در پوشه‌ای باز است که هنوز دستور git init در آن اجرا نشده، یا در مسیر اشتباهی (مثلاً یک پوشه بالاتر یا داخل یک زیرپوشه مثل public) قرار دارید.
راه‌حل: اگر در زیرپوشه هستید با cd .. به پوشه اصلی برگردید، و اگر پروژه جدید است گیت را راه‌اندازی کنید: 
git init
6. warning: in the working copy of '...', LF will be replaced by CRLF
علت: این پیغام خطا نیست، بلکه فقط یک هشدار عادی در ویندوز است که نشان می‌دهد کاراکتر پایان خط فایل‌ها به استاندارد ویندوز تبدیل می‌شود.
راه‌حل: کاملاً بی‌خطر است و می‌توانید نادیده بگیرید. اما اگر می‌خواهید دیگر این پیغام طولانی نمایش داده نشود، یک بار این دستور را بزنید: 
git config --global core.autocrlf true
7. nothing to commit, working tree clean
علت: بعد از آخرین کامیت، هیچ تغییری در فایل‌ها نداده‌اید (یا یادتان رفته فایل‌های تغییریافته را در VS Code با Ctrl + S ذخیره کنید).
راه‌حل: ابتدا فایل‌ها را در VS Code ذخیره (Save) کنید و اگر قبلاً کامیت کرده‌اید، مستقیم دستور git push را بزنید.
8. remote: error: File ... is 100.00 MB; this exceeds GitHub's file size limit
علت: گیت‌هاب اجازه آپلود تک‌فایل‌های بالای ۱۰۰ مگابایت (مثل ویدیوهای حجیم یا فایل‌های فشرده بزرگ) را در حالت عادی نمی‌دهد.
راه‌حل: فایل حجیم را از پوشه پروژه خارج کنید و اگر قبلاً کامیت شده است، کامیت آخر را بازگردانید تا فایل از لیست خارج شود: 
git reset --soft HEAD~1
9. fatal: unable to access 'https://github.com/...': Failed to connect / Recv failure
علت: اختلال در اینترنت یا تنظیم نبودن پراکسی/فیلترشکن روی ترمینال گیت.
راه‌حل: اتصال اینترنت را بررسی کنید. اگر قبلاً پراکسی دستی روی گیت ست کرده‌اید که الان خاموش است، با دستورات زیر پراکسی گیت را ریست کنید: 
git config --global --unset http.proxy
git config --global --unset https.proxy
